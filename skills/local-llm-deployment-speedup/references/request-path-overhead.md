# 缓存命中后的请求处理与图片优化

用于真实前缀已复用、但首响应仍慢，或图片重复处理的情况。先按[缓存诊断](cache-invalidation.md)确认实际命中与新增计算，再处理本章的软件成本；不要用请求处理提速掩盖后端重算。

## 1. 沿真实请求划分计时

分别观察排队、模板/分词、多模态准备、上下文预检、进程发送/接收、调度、模型首次计算和客户端非空内容。先用原生日志定位，需要时短时采集疑似函数；函数累计耗时可能重叠，也含诊断开销，不能相加当可追回时间。

检查服务端TTFT起点。预检、图片读取或中继可能在该窗口外，消除这些工作会先反映在客户端；同时记录服务端和客户端，不能移动计时边界制造提速。按[请求归属](measurement-contract.md#服务端指标必须归属到真实请求)关联回执，不把排队或别的请求混进去。

## 2. 按数据流去除重复准备与复制

| 检查点 | 可实施的改法 | 保持的语义与依赖 |
|---|---|---|
| 长历史占位匹配逐token反复切片 | 预解析候选token，定位可能起点后精确匹配，复用同请求内公共查找 | 模态/候选优先级、非重叠规则、完整图片占位与偏移 |
| CPU张量被重复pickle或编码共享存储 | 沿已有带外buffer通路按底层存储传输一次，再重建tensor view | dtype、shape、stride、offset、alias；特殊张量用兼容路径 |
| 上下文预检与正式请求重复渲染 | 保留本次只读预检结果，通过后复用并提交原发送缓存 | 触碰/淘汰顺序、统计、缺失判断；拒绝请求不提交，临时信息不泄漏到下一请求 |
| 接收帧后再次拷贝大张量 | 接收内存独立且寿命足够时构造view | 消费者结束前保持所有者；可复用环形槽仍需副本或可靠引用保护 |
| 图片重复转换相同格式 | 跳过无效复制；完全不透明输入用等价快捷路径 | 透明/半透明按原背景合成，颜色与像素一致 |

从热点函数读到调用者与消费者：只改发送端会漏掉alias和接收槽复用，只改预检会漏掉缓存提交时机。复用应限定在已证明相同的请求数据，不能把动态metadata跨请求长期缓存。

### 怎样编码与验证

先用原实现固定参考输入与输出，再修改一个有依据的重复区段。占位匹配测优先级、边界、多图与顺序；张量传递测共享存储、切片/步长、空张量和消费者寿命；单次渲染测有效/拒绝请求、缺图和缓存淘汰；图片转换逐像素对照包含透明度的输入。

随后在正常无诊断的进程中复核同条件完整请求、实际输入/输出和缓存用量，并走相关工具或图片续接。局部编码/拷贝微测不代表整次请求收益，图片像素或缓存一致也不代表模型识图正确；语义质量继续按[真实任务](../SKILL.md#操作者填写真实测试任务)验收。

## 3. 历史图片特征的持久复用

先核对原图内容、processor/encoder、权重、参数和特征表示能否构成可靠身份。允许复用时保存原特征，命中后校验完整性并返回相同数据；模型、图像或处理参数变化必须失效，不能仅靠文件名/URL匹配。

容量有界、可淘汰对象与使用中工作对象分开，避免清理时破坏消费者。对不可变大文件可缓存已校验的指纹元数据，发生变化后重新确认，避免每轮完整扫描权重。损坏记录按正常路径重建，不把坏缓存继续交给模型。

**图片特征持久化不等于文本KV跨进程持久化。** 重启后的旧图可以不再编码，文本仍可能冷预填充；新图编码也有必要成本。分别验证图片命中、文本KV和客户端等待，不能将一次暖请求的全部收益归给特征缓存。

慢准备期间如实际协议需要心跳，只用来保持连接和反馈状态；心跳/响应头不算首模型token。异常、取消、非流式和其他协议保留各自行为，不用早发空事件伪装计算加速。

验证旧图、新图、换图、改模型/参数、损坏、淘汰和使用中对象寿命，再从实际应用续问。默认保留原始图片与可重建历史，不通过删除图片降低等待。

## 4. 交付净收益

报告哪项重复扫描、转换、复制或准备消失，实际入口是否命中新路径，完整请求省了什么时间，以及相关功能与缓存是否保持。命中率不变也可以有效提速；软件成本已不再主导时转向剩余计算或传输，不继续无边界打磨微小函数。
