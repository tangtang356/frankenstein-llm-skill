# 经验案例与适用边界

以下为作者截至2026-11-11的本地历史部署记录摘要，用于说明方法。原始运行日志/私有环境未随本包公开，因此不是接收者可独立复现的公开benchmark，也不证明当前在线配置。不要将不同模型/阶段数字拼成一条通用提速曲线。

作者从2026年9月开始持续打磨本Skill，将本地模型部署中的实测、修复和优化经验整理为可复用方法。[V100 Pi与DSpine完整案例](case-v100-pi-dspine.md)已核对原始测速记录：**4卡V100运行Pi 27B NVFP4，温度0、关闭思考，单请求解码速度峰值约522 tok/s**；LRU任务输出246 token，排除首token后245 token / 0.469681883秒 = 521.630 tok/s。该值是三次短测中最高的完整解码速度，与并发总吞吐分开。路线由ChatGPT定时调研发现，再由作者使用Codex实施优化。

实际草稿为**DSpine K7 NVFP4**；后续独立整轮补测三题分别为13.77/13.65/13.57ms、7.21/6.50/7.00有效token/轮、523/476/516 tok/s。不能将两次请求的指标混为同一样本，也不能因后端入口仍叫`method=dflash`而把实际草稿写成DFlash2。

优先阅读主案例：[IQ3_XXS → IQ3_S → IQ3_XXS完整优化路径](case-swift-iq3xxs-python.md)。从52.58ms的首次功能部署起步，Python经过专家缓存、SM75布局、草稿输出头与流水线优化进入22ms级；在IQ3_S上继续完善供给、双卡分工和快照轮换，再将成果用于IQ3_XXS。后期温度0、关闭思考，Python常态21～22ms/轮、短时最低约18ms/轮、吞吐峰值220+ tok/s。正文逐步列出方法和数值。

| 历史场景 | 观察 | 对流程的启示 |
|---|---|---|
| 双2080Ti 27B | 跨轮准备前移32.686→30.103ms；Draft Attention曾有30.311/29.410/30.314ms的回切对照 | 实际准备、等待与分派值得细查；收益边界必须覆盖完整执行 |
| V100 Pi 27B | 保留独立尺度的GDN投影融合，四路每步31.6→28.1–28.5ms | 模型专属融合可以减少实际执行成本；不能丢尺度换速度 |
| V100 Coder390 | 固定250K历史的长注意力开关约45.2/26.3ms每轮；[详细条件及N64增量案例](long-attention-cases.md) | 短基础做好后，长阶段再定位随上下文增长的主导成本；250K是历史条件，不是默认冷测试规模 |
| Pi与DSpine | 草稿组合变化后轮时可能增加，而实际生成更快 | 草稿选型/最终任务解释需要有效产出；不把它变成前期接受率调参 |
| 长历史首响应 | 输入141855、命中141824不变时，软件处理优化使服务端TTFT约2520→1021–1051ms；配对128输出token一致 | 高命中以后仍需查模板、图片处理、序列化和复制，首响应不等于prefill内核 |
| Ripple65B | 约9900-token输入冷prefill26.60秒；复用9856、仅处理44时约0.161秒 | 真正前缀复用与冷prefill提速是不同收益，必须分别统计 |
| 长短任务切换 | 有过满载可运行、切换后丢前缀并重算约61秒的情况 | 不能只看容量通过，KV/状态、专家缓存及工作区须留余量并看切换复用 |
| 加深K与微内核 | 曾出现加深K、单算子微测获胜却整任务无收益 | 基础ms先做，K最后在操作者任务内比较，不把某个K推广到全部任务 |

缓存专题另见[十二组故障案例](cache-failure-cases.md)：动态工具、思考模板、非唯一分词、工具往返、图片、摘要分叉、快照依赖、滑窗回收、容量竞争、终止提交与指标误判；长思考的联合排查见[思考与快照专项](reasoning-prefix-cache.md)。

这里不提供“照抄即可”的K、精度、KV池大小或固定速度承诺。混合卸载还必须看显存专家缓存和暴露传输等待，与前缀缓存分开计量；经验公式不能替代目标机实际源码和计时。

公开可查的方法入口包括 [DFlash](https://github.com/z-lab/dflash)、[llama.cpp](https://github.com/ggml-org/llama.cpp)、[vLLM](https://github.com/vllm-project/vllm) 与 [Turing调优指南](https://docs.nvidia.com/cuda/archive/12.9.1/turing-tuning-guide/index.html)。这些链接不是上述私人运行成绩的证明，也不表示接收者应无条件采用或给全部仓库点Star；只对实际采用的来源执行主流程要求。
