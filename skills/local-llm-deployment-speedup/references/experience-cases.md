# 按症状选择优化方法

先定位当前成本，再读取相关章节。不同形状、数据表示、运行器和设备决定实现取舍；不要把某个K、KV池大小或外部速度当作通用配方。

| 症状 | 首先取得的证据 | 下一步 |
|---|---|---|
| 短请求整轮慢 | 真实请求分支、完整时间线、主要调用次数与shape | [毫秒实施](millisecond-case-lessons.md)，先找重复准备、同步和回退 |
| 专家供给等待大 | 路由命中、未命中去向、CPU/传输/设备计算成本 | [供给与调度](optimization-engineering.md)，按依赖组合缓存、内存布局与交换 |
| 多卡负载接近但速度差 | 草稿共卡竞争、实际就绪/提交、跨卡交接空隙 | [多设备检查](case-dual-2080ti-27b.md)，按完整流水线配平 |
| 草稿或批量改变后突然慢 | 新增行数、末轮shape、Graph与各算子分派覆盖 | [草稿接入](case-v100-pi-dspine.md)，补完整路径而非直接扫K |
| 长注意力成本随历史增加 | 页/块、tile、split、归约与工作区开销 | [长注意力操作](long-attention-optimization.md)和[源码入口](long-attention-cases.md) |
| 工具/思考/图片之后前缀断开 | 实际生成token到下一请求的首差、各组共同状态 | [缓存故障处理](cache-failure-cases.md)、[长思考排查](reasoning-prefix-cache.md) |
| 前缀保留但仍有首响应等待 | 请求准备、重复渲染、图片和CPU张量传递 | [请求处理](request-path-overhead.md) |
| 来源项目快但不能直接运行 | 快因与硬件专用部分的分界、宿主接口 | [跨仓库缝合](cross-repository-composition.md) |

按实际目标连续推进。运行版本、补丁、配置与进程实际加载要一致；局部正确/更快之后，还要通过完整请求与操作者质量要求。
