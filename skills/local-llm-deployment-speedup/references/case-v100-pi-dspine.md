# 草稿接入、形状覆盖与生成续接

用于接入新草稿、复用投机验证框架，或选定配置出现形状回退。草稿选型与K调优遵守[主流程](../SKILL.md)，不把日常执行优化自动变成接受率调参或训练任务。

## 1. 确认实际加载的草稿身份

同时检查权重、模型架构、tokenizer、tap/桥接、codebook或词表映射、验证协议和实际加载类。服务配置中的method名称可能是复用入口，不能仅凭一个字段判断运行结构。

对来源实现读清锚点token、位置、状态、分片与聚合协议，优先接到现有验证链；没有目标设备实现时按[机制移植](cross-repository-composition.md)改写所需kernel及配套。保留草稿与目标协议要求的dtype、scale、归一化和条件分数计算。

## 2. 查新组件是否增加无效工作

草稿使用局部窗口时，planner、页表、分区容量和主体循环都应对应实际有效窗口，不能只是读取时加mask、仍按整段历史分配和调度。单路与批量路径分别核对，不能把一种shape的收益推广到全部请求。

投影融合前核对各分支独立量化尺度和中间舍入，能共享输入准备不代表能统一scale。新草稿还可能挤占KV、状态、Graph或专家空间，按整套预算验证会话切换与续接。

## 3. 行数变化后检查完整快路径

记录真实Target/Draft/Verify宽度和末轮尾宽，检查量化、矩阵、注意力、采样Graph、collective、归约、GDN递推及状态提交是否覆盖。不要只修改主体投影，而让旁路反复回CPU或eager。

对小DtoH沿生产者→复制→CPU分支→下一提交查阻塞；准确host值已存在时复用，或者把判定留在设备/Graph，必要读取延迟到消费点。动态值仍随接受、取消和缓存恢复更新，不能用固定值顶替。

真实执行路径生效且局部数值通过后，比较完整轮和最终任务。新草稿可能每轮更贵但有效产出更多；这种组合收益与内核轮时降低分开解释。完成适用的K比较后保留实际任务更合适的配置，不为保留已写代码强选更大的K。

## 4. 生成结果必须能够正确续接

前端保留原token之后，继续检查Attention、Hybrid状态、滑窗和页映射的共同边界。最新生成检查点所需的窗口不能被当作无用页优先覆盖；引用与回收规则保持有界，不无期限pin全部状态。

真实生成→工具执行或用户追加→下一请求验证原token、状态恢复、新处理量和输出质量；重发原prompt只能覆盖其中一种路径。按[缓存故障处理](cache-failure-cases.md)和[长思考排查](reasoning-prefix-cache.md)定位，不能只靠扩池掩盖依赖缺失。
