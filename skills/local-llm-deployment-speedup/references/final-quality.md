# 阶段10：全部优化完成后的最终质量检查

这是最终交付的必做步骤。未做prefill专项时，阶段8后进入；做了prefill专项时，在阶段9及其缓存复验完成后进入。前面以ms和速度为主线、质量问题单独记录，不代表最终可省略质量检查。前期仍须及时处理执行错误，无需等到最后。

限定范围修复按本次目标检查实际结果与受影响能力，复用已有质量证据；不为修复单个问题要求重做整套部署、K调优或无关任务验收。交付时说明本次完成的范围。

## 检查最终实际部署

核对正式进程加载的主模型/后训练版本、权重量化与计算路径、草稿及K、KV/状态精度和管理、底座/内核、视觉、温度与思考、上下文和入口。全部检查必须对应这套最终配置，不能拼接不同中间版本的通过记录。

使用操作者指定的常用任务和实际需求，复用阶段6/8已在**相同最终配置**下留下的真实输出与执行证据，只补缺失项和后续改动影响的部分。没有必要为了“最后再查”重跑所有测速，也不临时扩成所有能力排行榜。没有指定任务时不能用短样例宣称最终质量验收通过。

## 按使用能力检查可用成果

| 能力/场景 | 应检查的质量 | 可用证据 |
|---|---|---|
| 代码及工程任务 | 需求完成、逻辑正确、可运行、没有遗漏约定能力 | 实际运行/项目相关测试及产物检查；仅生成代码不算运行成功 |
| 总结/问答/写作 | 对原材料的准确性、关键点覆盖、指令遵循、适合约定用途 | 可追溯原文/答案核对和操作者要求；不凭模型自评判通过 |
| 视觉 | 图片内容识别、图文关系、同图续接及换图后答案归属 | 实际图片与回答；需要真实任务图时不能只靠色块样例 |
| 工具/Agent | 真正执行正确工具、参数/结果关联、接回结果后完成任务 | 真实工具调用与产物；JSON可解析不能代替执行 |
| 长上下文/高思考 | 保留约定上下文、任务约束、完成回答，续接不丢关键内容/串状态 | 最终常用设置的真实长思考及下一轮；无权查看的内部思维不作为必需材料 |
| KV/量化/状态/卸载相关 | 复用结果属于正确会话与图片，恢复状态不损坏内容，近似取舍没有被隐瞒 | 冷/复用/追加与必要边界的已有或补充检查，前缀计数另列 |

按方案确定的能力选择项目；明确仅文本或无工具用途的项目注明不适用，不强迫新增功能。检查正常终止、明显重复/乱码/异常空输出和被截断的未完成任务；语气、长度等普通偏好与实际执行错误分开。

## 判断是否因优化退化

有适当的优化前输出、同模型参考配置或已确认质量样例时，对相同任务核对结果；无需随机生成逐字一致，比较可用性与约定正确性。后训练模型、权重量化或KV精度变化有特殊取舍时单列，不能假称纯性能优化。

没有可比基线仍要做绝对可用性检查，并明确“最终任务检查通过/存在问题，尚不能证明相对原配置无质量退化”；不编造基线，不为补历史关闭共享服务。普通问题按任务记录严重程度与影响，不能自行设满分门槛，也不能用综合速度掩盖必需功能失败。

## 质量结论与交付

留一份简明结果：最终配置身份、任务及完成要求、实际产物/输出、检查方法、通过/失败/未测/不适用、发现的问题与处理。性能结果与质量结果并列；有实测性能收益但质量尚未检查时，报告“速度已验证，最终质量未验收”，不称全部优化完成。

出现明确由改动造成的执行错误或不可接受退化，修复或撤回有关改动，复查受影响的质量、缓存和速度，不强制重做无关全部阶段。操作者可决定普通质量取舍，已接受的限制写清；错误工具执行、状态串用或未完成任务不能改写成通过。

检查后又改变模型、量化、草稿/K、KV/状态、模板或内核等影响行为的配置，最终质量结论失效于受影响部分，需相应复验；不能拿旧配置报告交付新组合。全部约定优化与最终质量检查完成后，才交付最终可用配置及每周调研启用状态。
