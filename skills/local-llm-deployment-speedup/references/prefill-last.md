# 阶段9：按需进行的prefill优化

**Prefill优化不能破坏缓存。先完成短ms、长上下文/前缀、常用设置和任务、K调优及最终对标；操作者仍需要冷输入优化时才进入本专项。** 用户明确只要求prefill专项可遵从其范围，但仍先核实当前缓存基线，不强制补跑所有无关阶段。

这里后置的是可选prefill性能专项；从零移植所必需的prefill实现、正确性检查及阻断模型运行的修复属于阶段3B，不推迟到本阶段。

## 先证明问题确实在必要的新输入计算

首token慢先按 [上下文与缓存](context-and-cache.md) 查实际命中和重算、图片重复编码、模板/分词、复制/序列化、排队等。高复用请求大量重算时修缓存；处理层慢就修处理层。首次全新长文没有复用机会，其prefill是有效工作，不能为提高命中率添加无用前缀或返回旧答案。

分开记录冷输入、真实前缀复用、实际生成后追加新输入。无另定规模从约10k输入起；接近满上下文的冷请求需要明确任务范围，不能默认扩测。模型已驻留不等于前缀命中，KV已分配不等于状态可复用。

## 定位和修改

从本机证据选择真正占时的投影、注意力、分块/调度、数据转换或内核路径，核对所选精度、shape、硬件和实现版本。纯prefill吞吐用实际处理token与对应计算时间，不拿总输入除以包含排队/图片等开销的TTFT。

固定语义与原始输入，优先等价执行优化。近似prefill、KV精度变化、上下文压缩/丢弃属于额外取舍，要单独说明并遵从操作者选择；不能当成无损内核提速。不要擅自删图片、工具、历史或思考以改善冷算成绩。

## 从重复工作入手的具体路线

先检查权重/激活是否重复转换、驻留专家是否又被gather到临时区、短请求是否反复分配大块缓冲，再看真正占时的投影或注意力。IQ3路径采用固定HC投影适配，以及MMQ通过指针表直接读取驻留专家；前者改善计算路径，后者减少准备与搬运。

新内核与供给需要配套：分块行数、流式阈值、供给环槽位、驻留与非驻留路径都应覆盖。把完整配套接通后再看冷输入和短新增输入；不用孤立kernel微测代替实际请求。详见[工程拆解](optimization-engineering.md)的prefill章节。

## 每个拟保留改动都复查缓存

至少复验受影响的：短生成后续接、长历史复用、长思考与工具结果续接、图片同图/换图，以及Hybrid状态边界。混合卸载还检查工作区增长是否挤占专家缓存或KV。对照实际命中计数、新处理量、首内容和decode/任务耗时，确保不是把prefill成本移给下一轮。

冷prefill更快而前缀频繁失效、重复图片处理、长思考重算或专家供给明显退化，不能交付为整套优化成功。修复该候选或恢复已确认组合；不以“冷吞吐提升”掩盖续接退化。

本阶段位于最终对标之后，形成新候选时补受影响的正式对照与实际入口验证，更新最终配置和结果，不能沿用阶段8旧组合成绩。**Prefill专项的最终交付必须再次写明缓存复验结果。** 然后进入 [阶段10最终质量检查](final-quality.md)，使用本次prefill改动后的实际最终配置，不沿用旧组合质量结论。
