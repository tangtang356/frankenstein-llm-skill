# 从供给到计算、调度的优化顺序

本篇用于专家卸载或CPU/RAM/GPU协作部署，具体实施见[工程拆解](optimization-engineering.md)。选择顺序由当前关键路径决定，供给已不占主导时直接处理剩余热点，不机械重做全部步骤。

## 1. 确认完整通路实际生效

核对主模型/草稿、量化、惩罚或grammar、Graph、并行窗口和缓存路径。请求选项可能使后端退回串行或CPU处理，开关存在不代表本次请求用了快路径。追分支条件，并用实际调用日志或trace证明命中。

## 2. 先解决供给大头

区分驻留容量、实际路由命中和未命中成本。文件读取已为零时转查RAM、CPU计算、搬运与预取等待；不要继续优化不存在的磁盘热点。把内存布局、交换缓冲轮换、驻留适配和发布事件接成完整组合，再判断净收益。

将CPU直接计算与准备＋传输＋设备计算＋排队进行同shape比较。设备算得更快不代表搬过去更划算；改了供给成本后重新核对分工，而非按固定比例卸载。

## 3. 按真实算子匹配现成实现

列主要矩阵的格式、维度、行数、路由、所在设备、次数及实际kernel，包含主模型、草稿与输出头。先找能复用的打包、布局、tile和归约路径，再写必要适配；不要给不同矩阵统一套开关。

草稿链中输出头或状态复制也可能占主导，不能只看专家。保留完整词表、量化与验证语义，通过实际权重/shape局部检查后接入运行器。

## 4. 配平完整流水线并减少状态复制

将草稿与验证的共卡竞争、前后段交接、独立投影和状态提交画在同一时间线上。就绪的后段及时提交；独立分支必须满足真实输入依赖和消费者寿命。分层数量相等不等于耗时平衡。

状态版本ring可减少额外快照复制，但必须保留拒绝/撤销所需版本；提交、有效行数、位置和下一轮恢复共同推进。结束窗口按实际有效输出提交，不能只裁短返回文本。

## 5. 迁移时继承机制，重新匹配表示与预算

更换模型或量化后，将旧改动区分为可复用调度/状态机制、需重配的格式/shape/分派，以及需重算的显存/RAM/KV/草稿工作区。按依赖继承有效组合，不因换了权重文件就丢掉已有优化，也不假设旧内核自动适用。

每个必要组合做短反馈与受影响续接，正式比较仍集中在主流程规定阶段。最终以[操作者任务](../SKILL.md#操作者填写真实测试任务)的可用成果、时间和质量裁决。
