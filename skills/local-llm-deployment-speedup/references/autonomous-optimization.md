# 自动调研、优化与跨轮接续

用户要求自主优化、长期委托或自动调研后实施时读取本章。它复用主流程的阶段与验收标准，增加持续执行方式，不另建每轮全套测试。仅要求完善技能、讨论流程或准备任务说明时，只做这些工作，不启动模型优化、Goal或定时任务。

## 执行范围沿用一次约定

从当前用户指令、有效部署记录和已有明确授权确定目标主机/部署、希望改善的表现、须保留的模型能力、允许的操作和完成依据。记录在原部署说明即可，不要求填表、JSON或再签一次方案；只缺影响下一步的决定时才询问，并继续不依赖该决定的工作。用户后续收窄、暂停或撤回的范围优先于旧记录。

| 模式 | 如何推进 |
|---|---|
| 只调研或只读诊断 | 调研、核对和报告；不因发现候选自动修改部署或发测试负载 |
| 已授权的自动优化 | 自行筛选范围内候选，说明选择后连续完成适配、修改、编译、测试和结果处理，不再以“是否实施/继续”为阶段关口 |
| 仅准备流程或日程说明 | 交付技能/说明；创建日程、启动本轮执行分别按用户指令处理 |

自动优化不等于自动获得所有机器和操作的权限。模型/精度/草稿/上下文/并发、重启窗口、正式服务切换和资源预算按已有约定执行；不是这些参数一变化就必须再问，只有所需取舍超出授权才询问。未约定改变的用户配置保持原值。允许实验但未允许切换正式服务时，先完成可做的实现和验证，再提交具体候选及结果，不能提前停在抽象方案。

默认的源码实现细节、兼容修复、合理构建方式、已授权测试内的故障定位和撤回本轮退化改动，由执行AI决定。缺少无关字段、报告格式、可选指标或新的改进机会，不构成停工理由。明确只允许某个瓶颈时，不扩成换模型、扫K、训练或近满上下文冷测。

## 每轮连续完成一个有结果的工作单元

1. **恢复进度并查现场。** 读取原记录的授权、当前阶段、保留版本、在测候选、作业标识和下一步；核对实际进程、源码/产物、配置与资源。已有编译、下载、测试仍运行就沿原作业跟进；超时或断连先查结果，不重复提交。存在其他执行者占用同一部署时，不并行写同一源码或争用测试服务；可先做独立调研。用已有任务/锁信息协调即可，不为此搭调度平台。
2. **先接未完成的工程，再检查提速空间并补相关调研。** 有明确下一步且条件未变时直接继续，不因新会话或定时触发重做盘点和六步全文报告。没有下一步或瓶颈已变化时，按下节主动检查当前部署的提速空间，不等待用户提供问题或上游发布更新。查上次之后与当前瓶颈有关的原始更新、修复和可迁移实现；没有新发布也可完成已知瓶颈。旧失败方向仅在版本、假设或证据有变化时重试，并写明变化。
3. **自行裁决候选。** 按现场成本、适配可能性及实际任务收益选择可完成的方向，保留来源/版本、实施理由和影响范围。新方案落在委托内就记录并实施，不等待再次确认；范围外候选另记，不阻塞范围内工作。没有值得实施的候选且没有未完成目标，简记原因并结束本轮，不硬造优化。
4. **实施、定位、继续。** 复用已接受补丁及有效阶段成果，沿主流程做受影响路径的检查；正常构建和验证有进展时跟进到结果。遇到可解决错误继续修复，不把首次失败当作需用户接手。无新证据的相同失败不无限重试，转向其他有依据的路径或记录确切阻塞。
5. **验证并处置。** 检查实际加载、可比的完整轮时/请求表现、受影响的真实生成续接及任务质量；按阶段需要做长上下文、正式对标和最终质量，不每轮无条件重跑全部阶段。收益未证实就标未证实；退化时只撤回本轮相关改动并检查恢复。通过的候选在已允许窗口和正式启用范围内直接落地，否则保留可交付候选与具体待决定事项。
6. **记录结果和接续点。** 写清源码已改、已编译、临时验证、正式加载、实际入口验收分别到了哪里，以及保留/撤回/未验证的依据。记录下一步能直接执行的动作和在途作业。报告实质结果、阻塞或需要的决定，不在每个阶段末尾询问“要不要继续”。

本轮以约定成果完成、候选已裁决且没有值得继续的路径、实际资源/执行额度到界或确需外部决定为边界。不要设“永远优化到最快”的无终点目标，也不能因为发了一条进度消息就结束尚可继续的已授权工作。无人为预算时不自创很短的限时提前收工；遇到宿主硬限制则如实保存未完成项。性能结果不能用降低质量、删历史/思考、清缓存或缩减必需能力换取。

## 主动检查当前部署的提速空间

“没有上游更新”不等于“当前部署没有优化空间”。自主优化范围内，结合现有实测、代码和实际加载路径寻找本机机会；已有可靠结论不重复全量profiling，缺关键证据才补最小采集。只读或仅调研任务使用现有证据，不为此发模型请求。

- **短任务完整成本**：按[毫秒优化](millisecond-optimization.md)查CPU准备、计算、H2D/D2H、P2P/通信、同步等待、重复分配/拷贝、算子回退、Graph及状态提交，找到暴露在完整轮次上的大头，不以GPU利用率或单kernel时间代替结论。
- **两类缓存与首响应**：区分前缀KV/混合状态复用和显存专家供给；核对实际生成续接、新增输入处理、图片/工具历史及请求排队。异常重算走[缓存破坏专项](cache-invalidation.md)，不能把冷请求慢当作缓存失败。
- **已有适用阶段的长上下文/真实任务**：从已完成阶段证据识别注意力/KV读取、草稿输出头、资源竞争或任务内调度成本；进入下一阶段仍遵从主流程，不为了找机会提前冷填满窗口、扫K或扩大测试范围。
- **实现与部署差距**：核对已有补丁是否实际编译加载、快路径是否命中当前shape/设备、参考仓库哪些机制仍可迁移。必要硬件成本和软件浪费分别说明，不把理论带宽上限当成必达速度。

在原记录中给出简短候选排序：**证据位置 → 当前耗时/重算或等待 → 可改机制 → 预期影响 → 最小验证**。预期收益能从同口径数据合理估计才估计，否则写待测；重叠耗时不重复相加，不用草稿K猜有效产出。按实际任务收益、实施成本和证据强度选择下一项，候选在授权内就继续实现，不仅交一张“建议优化”清单。

外部候选按[GitHub源码对照](github-runtime-comparison.md)追到相关commit、调用链、形状/硬件条件、配套改动和测试；同时判断本地是否已有等价补丁、已有但未加载或真正缺失。候选可来自其他引擎或其他模型的局部快路径，按[跨仓库组合](cross-repository-composition.md)选择宿主与来源部件，不限于升级当前引擎。仓库无更新不阻塞本机已知瓶颈，搜索/权限失败也不能写成无更新。

## 接续信息放回原部署说明

沿用 [部署执行](deployment-execution.md#一份接续记录) 中的一份记录，补充以下实际需要的信息即可：

- 执行模式、有效授权及其来源、已约定资源/服务窗口、用户后续调整；“未决定”不写成默认同意。
- 当前目标与阶段、最近验收的组合、实际生效版本和证据位置。
- 本轮候选、结果与失败原因；已查到哪个来源/版本，哪些方向等待新证据。
- 原作业标识/状态、未完成验证、下一步操作、真正需要用户决定的内容。

阶段变化、重要结果和退出/交接时更新。普通Markdown或现有TXT足够；不因文件名、缺字段或格式不统一重建档案。没有记录时先结合当前指令和现场补最小记录，继续可确认范围内的工作。其他人改过现场时重新核实受影响部分，不能用上次快照覆盖当前改动。部署信息和私有日志不写入公共技能。

## Goal与定时触发分别处理

本章提供持续执行流程，不自带调度器。用户明确要求启动Goal，且宿主支持时，将本轮目标写为可验收的结果；已有未完成Goal沿用，不重复创建。仅提到“像Goal一样持续做”或只准备技能时，不据此启动Goal。宿主没有Goal也可在当前任务里按上述循环完成工作，不能假称已启用。

用户另行要求定时执行时，使用宿主支持的日程工具，先检查已有任务、目标记录、时区和时间，沿用已有选择。周一/三/五只是可选频率，不分别锁定为调研日/实施日/测试日；每次都从实际进度进入完整循环。未完成作业仍运行时不再开一份。已开始的本轮优化应持续跟进，不另建定时轮询任务代替完成当前工作。

创建日程不证明本机/SSH、联网、写入或服务操作可用，也不证明日程会自动创建Goal。落地时核对宿主执行环境和权限、必要的常开条件及实际触发行为；未验证的衔接标未验证。技能更新不修改这些配置，不自动安装守护进程或绕过宿主审批。无人值守遇到外部决定时保存具体候选与证据，继续独立工作；无可继续工作才等待。

## 可复用的执行请求

以下是模板，需替换目标与范围，不是已经创建的任务：

> 对【目标部署/原记录】执行自动调研与优化。沿用其中和当前对话里已明确的授权与限制，先核对现场及上次作业，从未完成步骤继续。按当前瓶颈做增量调研，自行选择授权内有依据的候选，连续完成实现、编译、受影响路径验证和结果处置；授权内不反复询问是否继续。保留模型能力及有效成果，未授权改变的配置维持原值；正式切换按已约定权限和窗口执行。实测无收益或退化时撤回相关改动，写回证据、未完成项和下一步。没有合适方向就说明并结束本轮；超范围决定只问具体缺项。日程是否创建、执行频率及Goal是否启动，另按用户明确指令处理。
